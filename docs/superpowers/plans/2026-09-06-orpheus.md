# Orpheus clean application implementation plan

**Goal:** Extract the complete working current workflow into an independent local Orpheus application, with a new two-page interface and no legacy application dependency.

**Architecture:** A Python package owns deterministic media processing, ADK sessions/tools, immutable project artifacts, and Grafana evidence. A same-origin HTTP server serves the compiled React interface and bounded API. The lab remains a read-only reference.

**Tech stack:** Existing pinned Python/ADK/NumPy/FFmpeg/MCP stack; React and Vite for declarative browser UI, native media APIs at explicit event boundaries.

**Spec:** PRODUCT.md and DESIGN.md, with current owner decisions below taking precedence over historical document scope.

## Confirmed scope

- Local single-user production quality; GCP deployment is future work.
- Exactly `/` and `/workspace` application pages.
- Remove legacy/v1 compatibility; retain explicit, receipted provider failover.
- Preserve impact, sustained texture, mixed arrangement, perception, fitting, recording, reviews, sessions and Grafana workflows.
- No React effects or imperative DOM construction; native capture/playback APIs belong in small lifecycle adapters.
- Each source file under 800 lines, readable formatting, central runtime configuration.
- No copied secrets, original sessions, private media, generated logs or unrelated historical docs in the new repository.

## Implementation and ownership

- [ ] Backend: `orpheus/config.py`, media/measurements, projects, provider, fitting/texture/arrangement, perception, workflow tool groups, worker, takes, observability/Grafana; package imports only. Preserve existing tool signatures and receipts. Add migrated tests with synthetic fixtures independent of old assets.
- [ ] HTTP: `orpheus/web.py`, `http.py`, API handlers. Own JSON/multipart parsing and ranged file serving; exact same-origin loopback checks. No old handler inheritance. Retain all current endpoints at unversioned paths; add runtime config, real waveform and poster responses.
- [ ] UI: `frontend/src` feature components and external stores. Landing/library and workspace with shared Fit/Record/Review; explicit paid actions; same-time audition, numeric mapping edits, immutable approval, capture resource cleanup, Grafana disclosures.
- [ ] Operations: carry clean Grafana provisioning/compose files, configure runtime data outside source, standalone install/run instructions and checkpoints.

## Verification gates

- [ ] Run incumbent `python -m unittest discover -s v2 -p 'test_*.py'`; record pre-existing failures independently.
- [ ] Run new backend suite from Orpheus without old source paths in imports. Cover prepared hashes, impact landmark/anchor gates, mixed/staged rendering, controller tool loops, session persistence, provider failure, exported measurements, redaction/outbox, take lineage and human approval hashes.
- [ ] HTTP checks use a temporary data directory and synthetic FFmpeg media: valid upload, invalid/repeated fields, origin/host, bounded sizes, range playback, traversal rejection, run serialization, metadata and artifacts, assisted edit rejection and preservation.
- [ ] Build frontend and run its state/transport checks. Scan source for legacy imports/routes, effect hooks, dead compatibility branches and oversized files.
- [ ] Exercise complete local path and inspect desktop/mobile together; run Impeccable detector once after complete UI. Batch defects, fix, confirm at most once.
- [ ] Report paid provider and actual Grafana validation separately from synthetic tests; never equate mocked wiring with autonomous quality or human acceptance.

## Evidence and decisions

The incumbent has parent-module media and model dependencies plus inherited legacy HTTP routes. Its native impact and sustained render tools are active features, not legacy compatibility. Preserve them.

The owner explicitly chose local single-user scope and explicit provider failover. Browser import must save preparation only; a separate run action authorizes model inference.
